# 0003 — 筛选删除移入回收站，不做插件内撤销

## 状态

已接受

## 背景

新功能「筛选删除附件与笔记」要把选中条目下的链接附件与笔记按条件筛选后删除。删除有三种做法：彻底删除（`eraseTx`，从库中永久移除）、移入回收站（`deleted = true` + `saveTx()`，写 `deletedItems` 表）、移入回收站并另建一套插件内撤销记录。

三者的磁盘后果不同。彻底删除会连同附件在 storage 里的目录一起删掉，其中 `imported_url`（网页快照）在库内存了一份网页副本，文件真正被移除；`linked_url`（网页链接）没有本地文件，删与不删没有区别。移入回收站不碰任何文件，文件要等用户清空回收站才释放。

设计对话中已定：候选是选中条目的直接子附件与直接子笔记；入口是独立菜单项；对话框即模拟运行，用户点击删除前看到的勾选集就是待删集。

## 决策

**移入回收站，不提供插件内撤销。**

通知写明「已移入回收站」；待删集含网页快照时，另说明快照文件仍在磁盘、清空回收站后释放。

## 被拒的替代方案

- **彻底删除**：不可恢复，且删掉的是用户可能仍需要的网页副本。对 `linked_url` 它没有换来任何好处——那类附件本来就没有文件。
- **对话框里给「同时删除本地快照文件」复选框**：一次操作里同时存在可恢复与不可恢复两种后果，同样的勾选动作在不同行上的含义不再一致，用户无法从勾选推断后果。
- **插件内撤销记录**：与 `CleanSessionStore` 形状不同——那里记录的是字段旧值（一批 `Change`），这里是「一批被删除的条目」。合并成「撤销上次操作」会让「上次」指代含糊。回收站本身就是恢复路径，再维护一套是用两个机制做同一件事。

## 影响

- 被删子条目留在回收站，用户需自行清空回收站才释放网页快照占用的磁盘空间，通知对此明说。
- 恢复入口由 Zotero 提供，插件不提供。恢复方式是 `deleted = false` + `saveTx()`，与插件无耦合。
- 「清理」与「筛选删除」成为两条独立流程：清理产生字段变更并可撤销，筛选删除产生条目删除且不可撤销。
- 日后若要求「删除时真的释放磁盘」，应重新审视本条决策，而不是在对话框里补一个复选框。
