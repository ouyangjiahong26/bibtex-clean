# 0004 — 重复附件按文件名与 URL 分组，默认保留带批注的一份

## 状态

已接受

## 背景

合并重复条目时，Zotero 把两个条目各自的附件并到同一个父条目下，留下多份相同附件：同一 PDF 的多个副本、指向同一页面的多个链接。新功能「清理重复附件」要判定哪些附件互为重复、每组默认保留哪一份、删除走什么路径。

## 决策

**同一父条目内判定重复：文件附件（imported_file、linked_file）按文件名相同（忽略大小写）分组，链接附件（imported_url、linked_url）按 URL 精确相同分组；组内成员 ≥ 2 才算重复组。**

文件名忽略大小写对齐 Windows/macOS 文件系统语义，也覆盖合并双方大小写不一致的情况；URL 保持精确匹配，因为路径大小写不同的 URL 是不同页面。两类分组键带类型前缀，不会互相撞车。判定只在同一父条目内进行：不同父条目下的同名附件不是本功能要清理的现象。

**组内默认保留者：批注最多的优先，批注数并列时取添加最早的。**

删除带批注的附件会连带丢失批注，批注是用户不可再生的劳动成果；添加时间只是并列时的次序依据。对话框展示每份的标题、批注数与日期，用户可手动换一份保留。

**删除沿用 0003 的决定：移入回收站，不做插件内撤销。** 若删掉的附件带批注，通知说明批注随附件一起移入回收站。

## 被拒的替代方案

- **文件名相同且内容一致（MD5 校验）**：能杜绝同名不同内容的误报，但要读文件计算哈希，附件多时明显变慢；合并场景下同名附件几乎总是同一文件，残余误报由对话框里的大小、日期、批注数信息与人工确认兜底。
- **默认保留最早添加的一份**：若最早那份不带批注、另一份带批注，一键默认勾选就会删掉批注。
- **禁止删除整组（强制每组至少保留一份）**：用户明确想全删时会被卡住；回收站本身兜底误删。

## 影响

- 判定是纯数据层（`duplicateGroups.ts`）的纯函数，采集在 Zotero 运行时层（`duplicateAttachments.ts`），可分别快照测试。
- 删除管线（`moveCandidatesToTrash`）泛型化为只要求 `libraryID + itemKey`，筛选删除与重复附件清理共用同一实现与并发偏好。
- 通知接口的失败明细只读标题，两条删除流程共用。
- 若日后出现同名不同内容的误报反馈，可在判定里加可选的哈希校验，而不是改动分组与保留策略的形状。
